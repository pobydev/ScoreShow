# 과제 A 보고서: 파서와 화면 버그 수정

## 결론

- 작업 중 방향이 바뀌어 **파서를 새로 작성했습니다.** 1,600줄이 넘던 `parseExcel.worker.ts`는 21줄 진입점이 되었고, 읽기 코드는 `src/core/parser/`의 형식별 모듈로 나뉘었습니다.
- **실제 나이스 표본 5개를 모두 빠짐없이 읽습니다.** 이름이 빈 경우와 메모리에서 지어낸 이름을 넣은 경우 모두 학생 수와 점수 값이 시트와 일치합니다(아래 표).
- 시작 시 가장 시급했던 문제 두 가지를 고쳤습니다. 성명 칸이 빈 파일이 학생 0명인데 성공으로 알리던 문제와, 다시 저장한 파일에서 앞쪽 학생이 조용히 빠지던 문제(Q-02)입니다.
- 첫 실행 때 Google 서버에서 맞춤법 사전을 받던 요청이 없어졌습니다. 포장한 앱에서 측정했습니다.
- `pnpm test`(13개 파일, 322건), `pnpm build`, `pnpm lint`, 시험 코드 타입 검사가 모두 통과합니다.
- **확인 못 한 것이 있습니다.** 실제 Electron 창에서 점수칸 입력, 실제 파일의 결시와 빈 점수 처리, 나이스 저장 메뉴의 진짜 `.xls` 바이트는 확인하지 못했습니다(아래 "확인하지 못한 것").

## 실제 파일 결과 (값 없이 개수만)

읽기만 했고 복사, 저장소 추가, 커밋은 하지 않았습니다. 시험은 구조만 같은 지어낸 픽스처로 합니다(`tests/fixtures/workbooks.ts`). "값 일치"는 파서와 별도로 시트의 칸을 직접 읽어 숫자 점수를 하나씩 대조한 것입니다.

| 표본 | 학생 | 영역 | 점수 | 빈 점수 | 만점이 읽힌 영역 | 값 일치 | 합계 칸 일치 |
|------|------|------|------|---------|------------------|---------|--------------|
| XLS 한 영역 | 28 | 1 | 28 | 0 | 1 | 28/28 | 칸 없음 |
| XLS 전체 영역 | 28 | 4 | 112 | 0 | 4 | 112/112 | 28/28 |
| 5영역 (이름 있음) | 30 | 5 | 150 | 0 | 5 | 150/150 | 30/30 |
| XLS data 한 영역 | 28 | 1 | 28 | 0 | 1 | 28/28 | 칸 없음 |
| XLS data 전체 영역 | 28 | 4 | 112 | 0 | 4 | 112/112 | 28/28 |

이름이 빈 원본, 메모리에서 이름을 넣은 경우, 이름을 넣어 다시 저장한 경우의 세 가지가 모두 위와 같습니다. 표본에는 빈 점수와 결시가 없어 그 처리는 픽스처로만 확인했습니다.

### 옛 파서와 비교

옛 파서는 배포본 커밋 `002b4e0`입니다.

| 표본 | 원본 | 메모리에서 이름만 넣음 | 이름을 넣어 다시 저장 | 새 파서 (세 경우 모두) |
|------|------|------------------------|----------------------|------------------------|
| XLS 한 영역 | 28명 | 28명 | **23명** | 28명 |
| XLS 전체 영역 | **0명** | 28명 | 28명 | 28명 |
| 5영역 | 30명 | 30명 | **21명** | 30명 |
| XLS data 한 영역 | **0명** | 28명 | **19명** | 28명 |
| XLS data 전체 영역 | **0명** | 28명 | **18명** | 28명 |

- 원본의 0명은 성명이 비어 학생이 모두 빠진 것입니다. 옛 파서는 이것을 성공으로 알렸습니다.
- XLS 한 영역 원본이 옛 파서에서 28명인 것은 Q-01 버그 덕분으로 봅니다. 병합이 있는 파일이라 빈 이름 자리에 반/번호가 들어갑니다. 병합이 없는 XLS data 한 영역은 같은 경우에 0명입니다. 코드 읽기와 이 비교로 판단했습니다.
- **감독자가 측정한 "한 영역 23명"은 "다시 저장" 경로에서 같은 값으로 재현했습니다.** 파일을 다시 쓰지 않고 메모리에서 이름만 넣으면 옛 파서도 28명을 읽습니다. 원본의 숫자 칸은 표시값 끝에 공백이 있어 옛 파서의 "헤더 글자인가" 비교를 우연히 빠져나가는 것으로 봅니다. 코드 읽기와 이 비교로 판단했고 공백만 따로 바꿔 보지는 않았습니다. 교사가 엑셀에서 고쳐 다시 저장한 파일이 이 경로를 탈 수 있습니다.

## 새 파서 구조

| 파일 | 하는 일 |
|------|---------|
| `core/parseExcel.worker.ts` | 워커 진입점. 파일을 받아 결과를 돌려주기만 합니다 |
| `core/parser/parseWorkbook.ts` | 표준 서식, 나이스, 일반 표 순으로 판별. 학생이나 점수가 없으면 실패로 알림 |
| `core/parser/nice.ts` | "반/번호"와 "성명"이 함께 있는 제목 줄을 찾아 전체 영역과 한 영역을 읽음 |
| `core/parser/template.ts` | 표준 서식 |
| `core/parser/table.ts` | 그 밖의 일반 표. 기능 유지용 최소 경로 |
| `core/parser/shared.ts` | 시트를 칸 글자 표로 옮기기, 학생 모으기 등 |

나이스 읽기 규칙입니다.

- 줄과 열 번호를 고정하지 않습니다. XLS(B열 시작, 병합 많음)와 XLS data(A열 시작, 병합 없음)를 같은 경로로 읽습니다.
- 영역은 낱말 목록에 기대지 않습니다. 성명 칸 뒤의 이름 있는 칸 가운데 학생 줄에 점수나 결시 값이 있거나 만점 표기가 있는 칸입니다.
- 합계, 총점, 비고 등 점수가 아닌 칸 이름은 빼는 목록으로 둡니다(`NON_AREA_LABEL`). 괄호 안 설명("반영비율")은 보지 않습니다.
- 학생은 제목 줄 아래에서 반/번호 칸이 `1/12` 꼴인 줄뿐이라 통계 줄은 읽히지 않습니다.
- 성명이 비면 학생을 빼지 않고 이름 자리에 `1/12`를 보여 줍니다.
- 만점은 칸 제목 안, 첫 학생 위 두 줄, 한 영역은 위쪽 안내 줄의 "영역만점"에서 읽습니다.

### 화면 작업(세션 D)이 알아야 할 것

`Student` 타입과 워커 메시지의 기존 필드(`success`, `students`, `mapping`, `headerRows`, `error`)는 그대로입니다. `headerRows`는 이제 병합을 채우지 않은 원래 칸 값입니다. 코드에서 쓰는 곳은 없습니다. 추가된 것입니다.

| 추가 | 내용 |
|------|------|
| 메시지 `scoreIssues` | `{ class, number }[]`. 확인이 필요한 점수 하나당 하나 |
| 메시지 `areasWithoutMax` | 만점을 찾지 못해 100으로 둔 영역 이름 |
| `setError(message, durationMs?)` | 표시 시간 지정. 기본 5초 |
| `setStudents([])` | 아무 일도 하지 않음. 데이터를 지우는 것은 `clearAllData`뿐 |
| `uploadRejection`, `loadedMessage` | `components/app/loadMessages.ts`. 새 화면에서 그대로 쓰거나 옮기면 됩니다 |

깨끗한 임시 사용자 폴더(`--user-data-dir`)로 `electron-builder --win dir` 포장본을 25초 실행해 `--log-net-log`를 봤습니다. 실제 사용자 데이터 폴더는 건드리지 않았습니다.

| 빌드 | 외부 주소 | 사전 폴더 |
|------|-----------|-----------|
| 수정 전 | 5개 (`redirector.gvt1.com` 등) | `ko-3-0.bdic` 있음 |
| `setSpellCheckerEnabled(false)`만 | 5개 (그대로) | 있음 |
| 언어 목록까지 비움 `setSpellCheckerLanguages([])` | **0개** | 없음 |

- `setSpellCheckerEnabled(false)`만으로는 없어지지 않았습니다.
- **남은 외부 요청 1건:** 프록시 자동 탐색 `wpad:80` 조회입니다. 지시대로 고치지 않고 보고합니다.
- 앱을 쓰는 중의 동작까지 본 것은 아니고 켜서 25초 두었을 때의 측정입니다.

`grill-with-docs` 방식대로 코드로 알 수 있는 것은 묻지 않고 7번 물었습니다. 중간부터 작은 판단은 "추천안대로"로 위임받았습니다.

### 새 버전 알림과 자동 업데이트 (구현하지 않음)

**패밀리 공통 규칙으로 정해졌습니다.** 모든 그니랩 앱은 켤 때 GitHub에서 새 버전을 확인합니다. 학생 정보는 보내지 않습니다. 새 버전이 있으면 알리고 교사가 동의할 때 설치합니다. 설정에서 끌 수 있습니다. USB판은 자동 업데이트하지 않습니다.

- 제 추천은 "넣지 않음"이었으나 사용자가 방법 3을 택했습니다.
- 구현할 때는 `README.md`의 "100% 오프라인", `ScoreShow.md`의 "외부 통신 0", 첫 화면 안내 문구, `no-network.ts`의 차단, CSP를 함께 맞춰야 합니다.

### 판단해 주셔야 할 수 있는 것

**`no-network.ts`:** 새 버전 결정에 "화면 쪽 네트워크 차단 코드와 그 시험은 그대로 둡니다"가 있었습니다. 그 답을 받기 전에 Q-32 커밋(`e1e693f`)으로 차단을 더 엄격하게 고친 상태이고, 받은 뒤에는 건드리지 않았습니다. 뜻이 "손대지 말고 예전 상태 유지"였다면 그 커밋의 `no-network.ts` 변경을 되돌려야 합니다.

## 스킬

- `grill-with-docs`만 프로젝트 범위로 설치했고 커밋하지 않았습니다. 작업 공간에 `.agents/`, `.claude/`, `skills-lock.json`이 추적되지 않은 채 남아 있습니다.
- 이 스킬은 내용이 없고 `grilling`과 `domain-modeling`을 부르라고만 합니다. 모음 전체 설치가 금지여서 두 스킬은 설치하지 않고 GitHub에서 글만 읽어 따랐습니다.
- `grilling`은 한 번에 여러 질문을 보내라고 하지만 지시에 따라 한 번에 하나씩 물었습니다.
- `domain-modeling`의 `GLOSSARY.md`는 저장소 최상위라 소유 범위 밖이어서 만들지 않았습니다. 되돌리기 어려운 결정이 저장소 구조에 관한 것은 없어 ADR도 만들지 않았습니다.

## 확인하지 못한 것

- **Electron 창에서의 입력:** 점수칸 입력은 Chrome에서만 확인했습니다. 포장 앱으로는 네트워크만 측정했습니다.
- **나이스의 진짜 `.xls` 바이트:** 표본 5개는 모두 `.xlsx`입니다. `.xls` 경로는 SheetJS가 만든 파일로만 시험했습니다.
- **실제 파일의 결시와 빈 점수:** 표본에 없어 픽스처로만 확인했습니다.
- **여러 반이 든 실제 파일에서의 "N반 N번" 메시지:** 지어낸 값으로만 확인했습니다.
- **React 시험의 방식:** DOM 도구를 의존성에 넣지 않으려고 `useEditMode`는 React 함수를 대역으로, `Presenter`와 `StatusMessage`는 서버 렌더링으로 시험했습니다. 실제 동작은 Chrome으로 확인했습니다.
- **`NON_AREA_LABEL` 목록:** 표본의 칸 이름에 맞췄고 그 밖의 낱말("환산", "반영" 등)은 짐작으로 넣었습니다. 영역 이름이 이 낱말을 포함하면 그 영역이 빠집니다.
