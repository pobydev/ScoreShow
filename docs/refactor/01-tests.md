# 과제 1 보고서: 지금 동작을 시험 코드로 고정

## 결론

- 시험 10개 파일, 268건을 추가했고 모두 통과합니다. `pnpm build`와 `pnpm lint`도 통과합니다.
- `src/` 아래 제품 코드는 한 줄도 바꾸지 않았습니다. export 추가도 필요 없었습니다. 워커는 `self`만 바꿔 끼워 실제 진입점을 그대로 실행합니다.
- 이상 동작 34가지를 찾았고 고치지 않았습니다. 33가지는 시험에 지금 동작 그대로 적었고, 1가지(Q-34)는 코드 읽기로만 확인했습니다.
- 가장 심각한 것은 **Q-01**(빈 점수에 반 번호가 점수로 들어감)과 **Q-02**(앞쪽 학생이 조용히 빠짐)입니다. 두 건 모두 교사가 알아채기 어렵습니다.
- 픽스처의 나이스 양식은 코드에서 읽어 재현한 것이고 실제 나이스 파일과 대조하지 않았습니다. 그래서 각 이상 동작이 실제 나이스 파일에서도 나타나는지는 확인되지 않았습니다.

## 실행 방법

```sh
pnpm test                         # 전체 시험
pnpm exec tsc -p tests/tsconfig.json   # 시험 코드 타입 검사 (pnpm build에는 포함되지 않음)
```

### 구성에서 정한 것

- **Vitest 3.2.x**: 저장소의 Vite 5를 지원하는 마지막 주 버전입니다.
- **`vitest.config.ts` 분리**: PWA 플러그인을 시험에 끌어오지 않습니다.
- **`xlsx`를 `xlsx.mjs`로 고정**: Node는 기본으로 코드페이지 표를 함께 불러오는 `xlsx.js`를 고르지만 앱 번들은 `xlsx.mjs`를 씁니다. CSV와 xls 해석이 앱과 같아지도록 시험도 맞췄습니다.
- **픽스처는 코드로 생성**: `tests/fixtures/workbooks.ts`에 있고 이진 파일을 저장소에 넣지 않았습니다. 이름과 점수는 모두 지어낸 값입니다.

### 시험 이름의 `[Q-번호]`

`[Q-번호]`가 붙은 시험은 올바른 동작이 아니라 지금의 이상 동작을 적은 것입니다. 해당 버그를 고치면 이 시험이 실패하는 것이 정상이며, 그때 기대값을 의도적으로 바꾸면 됩니다.

## 다루지 못한 범위

- **실제 나이스 파일**: 원본이 없어 대조하지 못했습니다. 픽스처는 워커의 정규식과 주석에서 읽어 재현한 모양입니다.
- **나이스 xls의 실제 바이트**: xls 픽스처는 SheetJS가 쓴 biff8입니다. 오래된 코드페이지 인코딩이나 xls 확장자를 단 HTML 파일이라면 결과가 다를 수 있습니다.
- **암호 걸린 엑셀, 수식 셀, 날짜 형식 셀**: 만들지 않았습니다.
- **실제 브라우저 환경**: Web Worker와 structured clone, 실제 IndexedDB와 localStorage는 대역으로 바꿨습니다.
- **React 컴포넌트와 Electron, PWA**: `FilePicker`, `Presenter`, `PreviewPanel`과 `electron/`, 서비스 워커는 시험하지 않았습니다. 이 작업 공간에서는 pnpm이 Electron 설치 스크립트를 건너뛰어 Electron을 실행해 보지 않았습니다.
- **`src/core/storage.ts`**: 어디서도 불러오지 않아 제외했습니다 (Q-34).
- **코드 커버리지 수치**: 측정 도구를 넣지 않아 수치가 없습니다.
- **날짜 일련번호의 정확한 값**: 시간대에 따라 달라질 수 있어 Q-10은 "30000보다 큼"까지만 확인합니다.
